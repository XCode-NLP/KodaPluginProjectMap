# Карта проекта / Project map

Устанавливаемый плагин Koda Desktop. Агент изучает код и раскладывает проект на понятные части с описаниями, карта показывает их связи и прогноз влияния задачи рядом с обычным чатом. Код проекта плагин не изменяет.

## Использование

1. Выполните `npm ci` и `npm run pack` в корне этого репозитория.
2. Установите архив из `dist/` через «Маркетплейс → Установленные → Установить из файла». Для разработки выполните `npm run dev` и подключите папку репозитория.
3. Откройте «Карта проекта» в боковом меню или рядом с чатом. Нажмите «Построить карту». Сначала плагин сам разбирает импорты и показывает карту по папкам, затем одноразовый агент Koda читает README, манифесты и точки входа и предлагает иерархию частей проекта: имя, описание, роль, пути и неочевидные связи. Агент работает только на чтение (песочница, `access_policy: read_only`, отказ во всех запросах прав, кроме чтения и поиска) и тратит запросы к модели. «Обновить» переиспользует найденные части, пока они покрывают проект; «Пересобрать с агентом» спрашивает заново.
4. Двойной клик по части открывает её подчасти, а у конечной части её папки и файлы. Хлебные крошки, «←» и Backspace возвращают выше.
5. Выберите части или папки (Shift + клик для нескольких), нажмите «Добавить в чат». Либо наберите `@module:` в композере и выберите модуль по имени.
6. Попросите агента: «Объясни назначение модулей и сохрани смысловые группы» или «Покажи на карте, какие модули затронет добавление поля профиля. Объясни причины и что проверить».

Агент использует текущую модель и историю чата. Он получает инструменты `get_project_map`, `get_module`, `update_module_groups`, `set_change_impact`. Первые два только читают карту; последние изменяют данные плагина. Для группировки нужно получить полный список файлов через `get_module`, включая страницы `nextOffset`.

Сплошные стрелки подтверждены импортами, их толщина зависит от числа импортов; пунктирные — связи, которые назвал агент. Модули для ссылок `@module:` и прогнозов совпадают с частями, которые напрямую владеют файлами. Цвета прогноза различают прямые изменения, косвенное влияние и области для проверки. Нажатие на путь открывает исходник внутри панели. Смена чата меняет прогноз; карта остаётся общей для проекта. После изменения файлов прежний прогноз помечается устаревшим; при повторном открытии карта обновляется, также есть кнопка «Обновить».

Ссылки на модули раскрываются при фактической отправке сообщения, в том числе из очереди и при steering. Если плагин выключен или модуль удалён, отправка сообщает об ошибке вместо подстановки другого модуля. В read-only runtime инструменты плагина могут быть недоступны; ссылки продолжают передавать компактное описание модуля.

## Разбор кода и ограничения

- JS/TS: синтаксический разбор Babel, import/export/require и строковые dynamic import, относительные пути, локальные tsconfig/jsconfig `paths`, `baseUrl`, относительный `extends`, workspace-пакеты и простые `exports`.
- Python: лексический разбор import/from, относительные импорты и корень `src`. Строки и комментарии исключаются из поиска импортов.
- Go: одиночные и групповые импорты, алиасы и пакеты локальных `go.mod`.
- Остальные языки входят в базовую структуру по каталогам. Динамические пути, рефлексия, условия Go build tags и внешние tsconfig не вычисляются. Неразрешённые импорты отражаются в ограничениях.
- До 4000 файлов, не более 512 KiB на файл. Служебные/скрытые каталоги, известные бинарные форматы и ключи исключены. Git-проект учитывает `.gitignore`; запасной обход без Git использует встроенные исключения. Неполнота обозначается явно.
- Карта и прогноз — средство навигации и планирования. Связи по импортам не доказывают полноту поведенческих зависимостей; прогноз требует проверки кода и тестов.

Данные хранятся только в `userData/plugin-data/dev.koda.project-map`. Ни отдельный API-ключ, ни сетевые разрешения не нужны. Плагин поставляется отдельно от бандла Desktop; сам архив требует версию Desktop с расширениями SDK из этой реализации.

## Проверка

```sh
npm run typecheck
npm test
npm run test:integration
```

Smoke использует временный профиль (без агента: карта остаётся структурной) и демонстрационный проект, устанавливает реальный архив, запускает utilityProcess/QuickJS, вызывает MCP, проверяет панель, ссылки, просмотр исходников, темы, язык и разделение чатов. Живой запрос модели не выполняется.

Бандл включает Babel standalone, предоставляемый Desktop (MIT). Его лицензионные комментарии сохраняются сборщиком.

Для `test:integration` нужен checkout Koda Desktop с установленными зависимостями в `../koda-app`. Другой путь можно задать через `KODA_DESKTOP_ROOT`.

Для проверки в Electron выполните `npm run test:project-map:smoke` из Koda Desktop. Для другого расположения плагина передайте путь после `--`.

## Выпуск в каталог

Используйте Node.js 22.12 или новее. Тег `v<версия>` должен совпадать с версией в `koda-plugin.json`. Workflow `release.yml` проверит проект и приложит к GitHub Release архив и `SHA256SUMS`. Для записи в каталоге возьмите URL и SHA-256 из этого релиза. Формат записи описан в [KodaPlugins](https://github.com/XCode-NLP/KodaPlugins#формат-записи).
